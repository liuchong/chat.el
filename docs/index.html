AI Chat for Emacs

A pure Emacs AI chat client focused on coding workflows. Multi-turn conversations, tool calling, file operations, and session persistence — all without leaving your editor.

Get Started → Documentation

Built for Coders

An event-driven agent kernel with real tool use, inside one big Emacs buffer

🧠

Agent Kernel

A UI-agnostic event loop drives every conversation: tool calls, retries, steering, and cancellation all flow through one observable event stream.

🔌

Two Protocol Adapters

Generic OpenAI-compatible and Anthropic-compatible factories. Sixteen providers onboard; a new vendor is just a base URL, a key, and a model name.

🛠️

Real Tool Calling

Files, grep, patch, and shell tools with approval gates. Malformed calls get fed back to the model for automatic retry instead of dying silently.

🩹

Fuzzy Patch Editing

A matching cascade that tolerates whitespace drift, Unicode punctuation, and indentation differences, with atomic multi-file patches and real unified diffs.

⌨️

Async Shell Loop

Commands run as subprocesses with timeouts and output truncation that spills to files. Emacs stays responsive while the shell works.

💾

Sessions & Memory

Append-only JSONL sessions resume instantly and survive crashes. A user-curated memory.md is injected into every conversation.

📐

Stacked Project Rules

AGENTS.md files are discovered from the filesystem root down to your file, merged root-first with a global fallback — just like the best agent CLIs.

⚡

Differential Streaming

Responses render incrementally — only the unfinished block is redrawn per chunk. Markdown becomes a document in place: markers hidden, code blocks coloured by their real major mode, tables aligned by display width. Copying gives back the original source.

One Buffer, One Agent

No forced panels, no split layout — just a conversation. Every buffer is its own session, so agents run side by side naturally

Quick Start

Get up and running in under a minute

emacs-lisp 
;; 1. Add to your load path
(add-to-list 'load-path "/path/to/chat.el")
(require 'chat)

;; 2. Configure your provider
(setq chat-default-model 'kimi-code)
(setq chat-llm-kimi-code-api-key "your-api-key")

;; 3. Or use auth-source for secure storage
;; machine kimi-code-api user api-key password YOUR_KEY

;; 4. Start chatting
;; M-x chat

Modular Architecture

Runtime modules are organized under `lisp/agent`, `lisp/core`, `lisp/llm`, `lisp/tools`, `lisp/plugin`, `lisp/ui`, and `lisp/code`

chat.el

Entry point and command wiring

lisp/agent/chat-agent.el

Event-driven agent kernel: turns, native tools, steering, cancellation

lisp/plugin/chat-plugin.el

Plugin host for Emacs-native agent tools

lisp/core/chat-session.el

Append-only JSONL session persistence

lisp/llm/chat-llm.el

Provider abstraction and async request handling

lisp/llm/chat-llm-claude.el

Anthropic compatible protocol factory

lisp/core/chat-stream.el

SSE parsing, chunk handling, error surfacing

lisp/tools/chat-tool-caller.el

Tool prompt contract, parsing, and execution

lisp/core/chat-approval.el

Approval flow for risky tools and tool creation

lisp/core/chat-files.el

File tools, patch engine, fuzzy replace, unified diffs

lisp/core/chat-project.el

Stacked AGENTS.md discovery and injection

lisp/code/chat-code.el

Code mode entry point and programming workflow
